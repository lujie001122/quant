# research/width — 持仓宽度能否在回撤≤20%下把仓位/收益抬上去

分支 `research/width`（main 未改动）。全期 2019-01-01→2026-11-13，`--momentum=simple`，数据 `data/kline_qfq` 前复权缓存，引擎 backtrader。

基线命令（其余全部配置 = 实盘口径）:
```
.venv/bin/python3 backtest_bt.py --momentum=simple --start=2019-01-01 --end=2026-11-13 \
  --concentrated-pyramid --top-n=5 --trail=e1 --lookback=10 --trend-entry --warmup
```

口径说明:
- 夏普统一用净值曲线口径（日收益、无风险利率 2%/年，`research/entry/analyze.py`）。基线 0.66；引擎控制台口径为 0.63（同一曲线，日收益/无风险利率处理不同）。两种口径的达标结论一致：控制台口径下全场最高也只有 0.63，同样低于 0.75。
- 平均仓位取自 dump 的 `equity.cash/value`（1-cash/净值），与引擎 `exposure` 记录逐日一致（基线 44.731% vs 44.731%）；`--no-timing` 时引擎不记 exposure 序列，故统一用现金口径。**未改引擎任何交易逻辑。**
- 达标线：年化≥13% 且 回撤≤20% 且 夏普≥0.75，三条同时满足。

**结论速览：四组全部不达标。最高年化仍是基线 10.23%。宽度（top-n）加不出仓位也加不出收益；加仓批数把仓位压低、回撤翻倍。**

## 6. 结论：有没有一条能在回撤≤20%下做到 13%+

**没有。** 三组主测 + 邻域 + walk-forward 全部低于 13%，也全部低于基线。

卡在四个地方，都有数字：

1. **宽度不是仓位的水龙头。** top-n 5→15，并发只数 4.41→5.06（顶到 5.63 就不再涨），平均仓位 44.7%→44.9~50.3%。原因是单槽建仓只投 0.5 槽、确认加仓又稀，放开“允许买谁”并不能凭空生成入场信号。
2. **单槽基数是绝对金额，不随净值走。** `fund_per_etf` 固定 ¥58,666（config: max_per_etf 220000 × 0.8 ÷ sizing_n 3）。期初占净值 26.7%，期末净值 47.4 万时只占 12.4%。这才是平均仓位 44.7%、且逐年从 59%（2019）滑到 31%（2026）的真正来源——不是 top-n。
3. **两种“抬仓位”的杠杆都在加风险而不是加收益。** 放宽加仓批数：仓位 44.6%→38.5%，回撤 12.9%→35.0%；放大单槽（此前结论 0.75/1.0）：年化 10.24→8.81→8.21。加仓位在这个信号集上是单调加尾部风险。
4. **择时是唯一被验证有效的风控，宽持仓下也依然有效**（4 个宽度全部 开>关 的回撤），它只压掉 1.5~6.1pp 仓位，救不回 13% 的缺口；反过来，关掉择时也换不到 13%——最好的一档 t8(关) 只有 9.49%。

**距达标差多少**：基线 10.23% / 12.86% / 0.66（控制台口径 0.63），差 2.77pp 年化 + 0.09 夏普；全部宽度变体年化至少再低 0.68pp、夏普低 0.04 以上。差距不是“差一点仓位”，是宽的每一档都在同一个方向上更差。

如果还要继续这条路，唯一没被这轮测过的数学出口是**按净值重算单槽基数（目标权重口径）**：用现有成交序列折算，单槽随净值缩放后平均仓位约 67.5%（不是 95.6%），而 `research/structural` 的目标权重引擎 95.6% 仓位对应 21.10% 年化 / 31.96% 回撤——回撤直接破 20% 线。也就是说：仓位、收益、回撤在这套信号上是同一个变量，想拿 13%+ 就得接受 25%~32% 的回撤；想把回撤压在 20% 内，年化天花板就在 10% 附近。
